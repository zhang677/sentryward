Proving a barrier phase without listing schedules

SentryWard runs a kernel once, then proves that no other interleaving could complete an mbarrier phase differently. This page uses a toy kernel to show how it does that: one producer thread loads two tiles with TMA. One consumer thread arrives on the barrier to say it is ready, waits for the phase to complete, and then reads a tile.

The set of events you have run is always an ideal

      
Whenever an event has run, all of its predecessors have run too. A set with that property is called an ideal, or downward-closed set, of the graph. Every partial run is an ideal, and every ideal is a partial run of some schedule. So the question "can any schedule complete phase 0 too early?" becomes "is there an ideal where both counters are zero but some effect on the barrier is missing?" That question is about one set at a time, not about orderings.

    

  


  

    
Step 3

    
One minimization per effect

    

      
First the totals must balance: total arrivals equal the count from mbarrier.init, and the bytes announced by expect_tx equal the bytes landed.

      
SentryWard then tries a shortcut that ignores order: it assumes any subset of the effects can run and takes the worst case. In this kernel the shortcut fails for both versions. Ignoring order, both arrivals and both landings could run without expect_tx, which leaves −1024 bytes, so the shortcut cannot rule anything out. Only the order expect_tx → TMA issue → landing excludes that, and only the solver uses order. (A fused arrive.expect_tx with a single arrival would pass the shortcut with no solver call.)

      
The solver works as follows. For each effect that is not an arrival, the checker asks for the ideal with the fewest bytes outstanding that has every arrival in it and that effect left out. Forcing the arrivals in is safe because, with the totals balanced, missing any arrival keeps the phase open anyway. If the minimum is above zero, no schedule can complete the phase without that effect. If it can reach zero, that ideal is a counterexample.

    

    

    

    

    

      

      

        
How the minimum is found without listing ideals

        
    
          
  • Each effect becomes a node between a source s and a sink t. A landing that removes bytes gets an edge from s with that capacity. An expect_tx that adds bytes gets an edge to t.
    • 
          
  • Each ordering u → v becomes an edge v → u with infinite capacity. If v is on the source side and u is not, the cut would be infinite, so the source side is always an ideal.
    • 
          
  • Arrivals get an infinite edge from s (∞ in), and the left-out effect gets one to t (∞ out).
    • 
          
  • After max-flow, the nodes still reachable from s form the minimizing ideal. Its byte count is the cut minus all bytes removed by landings.
    •

Step 5

    
Six phases on one barrier, and why the solver is needed

    

      
Steps 1–4 checked a single phase. Real kernels reuse a barrier for many phases, so before it can prove anything the checker has to decide which effects belong to which phase. This kernel uses one barrier, full, for six rounds of a two-slot pipeline. In round k the producer loads tile k into slot k mod 2 and the consumer reads it. The consumer's arrive in round k says it has finished reading tile k−1, so that slot can be refilled in round k+1. Each phase expects two arrivals, one from each thread.

      
The two versions differ in one line: the order of the producer's expect_tx and arrive.

What this page simplifies

      
    
        
  • SentryWard lowers most instructions to an issue event and a done event. Steps 1–4 draw each pair as one box; Step 5 draws them separately.
